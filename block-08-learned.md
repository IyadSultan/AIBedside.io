  <h1>What we learned at KHCC</h1>

  <p class="demo-lead">At King Hussein Cancer Center we did not start with a model. We started with a room of people who already knew the work. These are the habits that let the work survive the first week on a ward.</p>

  <ol class="learned-stack">
    <li class="learned-item">
      <span class="learned-n" aria-hidden="true">1</span>
      <div>
        <h2>Listen to each other</h2>
        <p>Clinicians, pharmacists, and nurses are not an audience you demo to at the end. They help build the tool and decide how AI enters the ward. If they are not in the room, the tool will not last the first week.</p>
        <p class="learned-who" aria-label="Who must be in the room">
          <span>Clinician</span>
          <span>Pharmacist</span>
          <span>Nurse</span>
        </p>
      </div>
    </li>

    <li class="learned-item">
      <span class="learned-n" aria-hidden="true">2</span>
      <div>
        <h2>Buy-in, not resistance</h2>
        <p>People resist what was done <em>to</em> them. They adopt what they helped shape. Listening is how you get buy-in. Buy-in is how you avoid a quiet boycott.</p>
      </div>
    </li>

    <li class="learned-item">
      <span class="learned-n" aria-hidden="true">3</span>
      <div>
        <h2>Write a professional list of requirements &mdash; a PRD</h2>
        <p>A PRD is a product requirements document. Who it is for. What it must do. What it must never do. What &ldquo;done&rdquo; looks like. Without that list, engineers guess, and you get a demo nobody asked for.</p>
        <p class="learned-skill">You already have a skill for this: <a href="{{ site.baseurl }}/assets/SKILLS/prd-builder.skill" download="prd-builder.skill">prd-builder</a> &mdash; messy notes in, a written brief out. Same pack as <a href="{{ site.baseurl }}/block-03-skills/">Block 3</a>.</p>
      </div>
    </li>

    <li class="learned-item">
      <span class="learned-n" aria-hidden="true">4</span>
      <div>
        <h2>Ask for the code. Then query it.</h2>
        <p>Do not be shy. Ask the engineers for the code. Open it. Ask a model what a function does, and why a number is calculated that way. You do not need to write the code to own the question. You still decide if the answer is safe for a child on the ward.</p>
      </div>
    </li>

    <li class="learned-item">
      <span class="learned-n" aria-hidden="true">5</span>
      <div>
        <h2>Put the data in one place</h2>
        <p>Scattered spreadsheets are not a data strategy. One store, one set of rules, one number the team can trust. If every unit keeps its own copy, you will argue about whose figure is real.</p>
      </div>
    </li>

    <li class="learned-item">
      <span class="learned-n" aria-hidden="true">6</span>
      <div>
        <h2>Start with the governance that lets you work</h2>
        <p>You cannot process data because someone is enthusiastic. You process data because a policy, an IRB, and a data-use agreement say you may. Write those rules first. Then the work can move.</p>
      </div>
    </li>
  </ol>

  <div class="learned-floor" role="note">
    <p class="learned-floor-kicker">The floor</p>
    <h2>Cybersecurity comes first. Everything else comes after.</h2>
    <p>Be careful of any breach. A clever tool that leaks a name is not a clever tool. Lock the door before you furnish the room.</p>
  </div>

  <div class="block-section" style="margin-top:1.75rem;">
    <h2>Take-home</h2>
    <div class="callout callout-takehome">
      People in the room. A written PRD. One data store. Rules that allow the work. Security before everything else.
    </div>
  </div>
